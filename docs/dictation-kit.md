# Dictation kit

`@byokit/dictation` is the owner-confirmed name. The package is publishable at 0.1.0, with the injected system path qualified by the Android consumer flow. This specification applies the delegated decisions to integration map v3 section (c): shared on-device speech detection in `@byokit/audio`, injected audio ports, normal ChatGPT catalogue route, provider execution in a child process, publishing only through the normal merged-main release tooling.

The kit returns text; it never sends a message or inserts into an app's draft. The consumer owns that action, microphone permission/arbitration, native speech recognition and recording. Browser and React Native consumers use the portable main entry. Node hosts use `./node`; credentials remain on that host and devices receive only transcripts through an app-owned transport. There is no dependency on realtime.

The portable `Dictation` supports file bytes/Blob and live PCM16 mono at 16 kHz, supplied by `AudioMic`. The PCM stream's idempotent `stop()` stops production and unblocks its iterator while retaining queued captured frames until the iterator ends. Finish drains that queue before final inference even when a preview was in flight; cancellation stops capture and discards it. A native system recognizer supplies its own capture with `onDevice: true`. An unavailable language pack becomes `needs-download`. `onDeviceOnly` refuses remote engines before accessing credentials or opening the microphone. Engine adapters expose explicit capabilities and do not silently fall back to billed calls.

The fixture `fixtures/conformance/dictation-typescript.json` owns partial stability, settling and overlap joins. Reread engines expose only words that two readings agree on; shown words remain stable. Whole-word replacements apply only to finals. Speech windows are read once per second. Generic engines finalize after 500 ms silence; the RN Whisper engine retains the complete recording through pauses and always reads it freshly at finish. `listen({maxSeconds})` bounds app-injected PCM capture, including silence and settled turns, to a finite positive number of seconds (default 300). Invalid limits yield `unsupported` before capture; exceeding a limit stops capture and yields `too-large`. Native system recognizers own their capture limits. A pause with no unread speech causes no further inference on generic-engine finish. Silent windows are discarded without inference. The host must stop capture to unblock iteration. Finish is idempotent; cancel aborts inference and yields no transcript. Provider engines finalize per utterance; they do not claim native streaming deltas.

`systemEngine(native)` forces local recognition. `whisperEngine({binary, modelPath})` runs an explicitly supplied whisper.cpp CLI with no inherited environment, using scratch WAV and JSON output. The app owns model distribution; `installModel` verifies byte length and SHA-256 through an injected store and deletes invalid downloads. No frozen model catalogue or unverified hashes are shipped. `whisperRnEngine({model, initWhisper, settings})` injects whisper.rn 0.7.2 as an optional peer, without native imports in the portable entry. The native binding, model, microphone and idle-release policy remain app-owned. The adapter retains one lazily initialized context, serializes inference, forwards abort to the native job, and drains inference on explicit `release()`. The Android consumer proof covers the injected system path, not whisper.rn or a model.

Whisper settings cover host-selected model, language, initial prompt/vocabulary, threads, gain, energy VAD (or an app-supplied neural detector from `@byokit/audio`), file chunking, beam/best-of and temperature fallback. Defaults and validation ranges are authoritative in the package README and `whisperSettings()`. File gain/clipping, optional 20 ms energy VAD with padding, chunking and preceding-text hints are shared by the RN adapter and desktop WER runner. Default recordings longer than 30 seconds use 30-second windows with 5-second overlap, merging matching decoded phrases rather than cutting at token timestamps; merged ranges carry range-level segment offsets. Explicit `chunkMs` retains non-overlapping windows. Live `Dictation` reads optional `capture` settings. Generic defaults remain RMS 0.015/500 ms; RN uses a gain-compensated RMS floor of 0.0025 and 10% of the recording's peak level for previews. The final retains quiet audio below that gate. Native segment offsets use hundredths of a second and are mapped back to original audio for single-window ranges. Word timestamps are refused because the binding returns segment offsets. RN defaults recommend host-supplied base.en q5_1, six threads, English (auto only when the host declares a multilingual model), greedy decoding, full-window audioCtx 0 per chunk and no token timestamps. Segment metadata never cuts audio. Upstream 0.7.2 ignores audioCtx; zero preserves full context in patched hosts too. App-supplied vocabulary/context is applied only to final/file readings, never live previews.

`byokit-dictation-wer` runs an app-passed desktop CLI/model over attributed synthetic clean/noisy/fast/technical-name fixtures and manifest settings profiles. It reports per-clip and micro-averaged profile WER plus wall-clock latency/real-time factor, verifies clip hashes, and includes 34 relayed synthetic regressions plus separately gated 66-, 97- and 300-second joined recordings. A persistent CPU backend built from whisper.rn 0.7.2's vendored whisper.cpp reproduces its decoding without a phone; repeated measurements and historical profiles expose accuracy/wait tradeoffs. A separate path-filtered CI job caches the model/engine and gates short and long WER independently against recorded baselines with one absolute percentage point tolerance. CI measures every clip once with two threads and saves the build/model cache before inference; local multi-repeat profiles retain their configured threads. CLI latency includes fresh model initialization; persistent-backend latency excludes loading. A configurable inference multiplier estimates phone-like wait but does not qualify phone latency. Fixtures, provenance, regeneration scripts and command ship with the package; tests substitute a fake CLI without model/network access. Neither native model accuracy nor physical microphone capture is claimed by adapter wiring tests.

`chatgptEngine({access})` uses the selected person's accounts-managed sign-in; the callback refreshes via the accounts runtime before returning access and accountId. Each request runs in an isolated child, with BYOKit's own originator. This is a normal offered subscription route without a flag. A provider refusal returns `not-included`, never an API fallback. The endpoint is undocumented and only fake-tested here.

`openaiEngine({key})` defaults to `whisper-1` for file/utterance transcription and timestamps. `openrouterEngine({key|access, model})` uses its sign-in key or explicit key; both routes are labelled API key (billed per use) and not offered by default. Endpoint overrides are restricted to HTTP loopback fakes. HTTP redirects are refused. Keys never appear in arguments, environment or errors. Inference runs in a fresh child with an empty environment unless the app explicitly passes one. Cancellation disconnects the child, aborts HTTP or terminates the passed binary, and removes scratch files. Processing has a configurable 60-second timeout and a 25 MB input limit.

Language and supported segment/word timestamps propagate from provider responses; unknown usage/cost is left absent. WAV duration is measurable locally; compressed input duration requires the provider's response. Usage reports free/subscription/minute basis and returned token/cost values. Native system usage is free. Punctuation defaults to the engine's normal behavior; the system port gets an explicit flag, remote APIs receive a prompt hint (not a guarantee), and ChatGPT cannot control it.

Sources checked for the implemented wire contracts: [OpenAI transcription reference](https://developers.openai.com/api/reference/cli/resources/audio/subresources/transcriptions/methods/create) and [OpenRouter transcription guide](https://openrouter.ai/blog/tutorials/transcription-on-openrouter/). Native streaming API-key transcription/client-secret minting, model caching, native module bindings and vendor/model qualification remain future work. The [Android emulator consumer](../examples/dictation-android/README.md) runs the public kit entry through real SpeechRecognizer/Binder callbacks from a deterministic local fixture RecognitionService. It qualifies local port wiring, stable partials, final replacements/settling, usage, language and cancellation without claiming microphone recognition accuracy.
