# Realtime voice lift

The named first consumer is muxr. Version 0.1.0 lifts its four native speech-to-speech routes: ChatGPT subscription voice, OpenAI, Gemini and xAI with an API key (billed per use). ChatGPT is a plain catalogue route, with no feature flag or approval gate. Its terms are labelled as data. Provider selection, prompts, tool authorization and internal identifier masks belong to the app.

The launch decisions supersede the older extraction map: no audio foundation dependency; injected microphone, capture, playback and route ports; every provider adapter runs in a kit-owned child process; ChatGPT uses fresh access from `Accounts.access(member)` and defaults to BYOKit's originator. Apps may supply their own validated signaling identity. The kit never reads another tool's login or runs its CLI. Explicit interruption aborts unfinished tool calls. OpenAI and xAI cancel the active response; Gemini retains server VAD interruption and rotates the provider session for an explicit interrupt. ChatGPT retains native speech interruption and preserves client delegations across ordinary user turns; an explicit interrupt closes its call and opens a fresh one, rather than guessing an undocumented cancellation packet. Completed tool side effects are never rolled back.

The portable entry exports the bounded `realtime.*` frame vocabulary, parsers, `AudioPorts`, `realtimeClient`, error types, words and provider catalogue. `./webrtc` exports browser WebRTC and a lazily loaded RN peer (the app supplies `react-native-webrtc`). `./node` exports `realtimeEngine`, `toolBridge` and `appBridge`. The initial surface retains the extraction spec’s frame-based seam so the existing carrier can consume the lift directly.

`realtimeEngine` accepts `{ engine, auth, instructions, tools, bridge, emit, model?, voice?, redact? }`. Keys are injected as `{kind:'key', key}`. ChatGPT accepts `{kind:'plan', access: signal => accounts.access(member, signal)}`. The parent resolves access, transfers it only over the child's private stdin, and never puts it on the device stream. The child dials only the selected engine endpoint. Endpoint overrides are limited to loopback fakes. The parent bounds lines and pending input, discards child stderr, redacts credentials and app patterns, and terminates then kills the child on close.

Tool handlers run in the app process. `toolBridge` enforces an allowlist, 16 KB arguments, idempotency per call id, 128 remembered calls, eight active calls, aborts, per-tool watchdogs and 8,000-character results. App wording for tool failure is injected. ChatGPT delegates through the tool named `delegate` with `{request}`; the app supplies its planner. Retransmitted delegation IDs do not re-run, and identical requests in the same provider turn share one result.

`delegationHandler` sends structured `{name, arguments}` requests to a separate app-supplied tool bridge and ordinary prose to an optional app planner. Named delegation targets remain tool arguments; the app owns lookup, validation, authorization and receipts. Invalid structured input never enters the planner. `toolBridge({app})` composes semantic app request/reply handling; the parent routes device app results to it and cancels pending requests on close.

`realtimeAuthCheck` is a bounded advisory saved-sign-in lookup with `ready`, `signed-out` or `unknown` results. The existing `result` promise and `onStatus` keep their status strings; additive `details` and `onResult` provide `{ state, reason?, message? }`. A peek may return a boolean or `{ state, reason? }`; known failure reasons are `credential-permissions`, `login-expired`, `missing` and `unknown`, with fixed plain messages. The injected `peek` must be read-only and never prompt, refresh or start login. Optional engine `authCheck` runs independently of startup and is cancelled on close; it never gates access, closes the session or claims entitlement. Credential acquisition through `auth.access` remains separate. Lifecycle reports use the existing `realtime.say` / `client.speak` path; the app owns subscriptions, confirmed outcomes, wording, push delivery and call wake/sleep policy.

The host owns tool watchdogs and failure wording; the child only proxies bounded requests and cancellation. Engine `hangup(text)` supplies app phrase policy and closes after the next agent transcript; `authFailure(error)` supplies sanitized credential-error remedies. Transcripts retain 4,000 UTF-8 bytes, state details 500, close reasons 2,048, without splitting Unicode. Empty ChatGPT transcripts do nothing. Parent disconnection waits for child stdio to drain, preserving final provider reasons.

ChatGPT's media-start frame is emitted while credential lookup and isolated-child startup proceed independently. Early offers remain queued behind the private credential/config line. `signalingIdentity: {originator?, userAgent?}` uses bounded printable ASCII and defaults to `byokit`; it changes no credential destination. Offline ordering tests do not establish a live remote-signaling latency improvement.

`realtimeClient` consumes an app-provided stream and audio ports. It waits for `microphone.acquire()` before capture or WebRTC media, releases on stop, caps pending microphone bytes at 96,000, observes synchronous send admission, emits turns and states, and forwards app request/reply frames. Playback owns drain and output flow control. Opt-in `capture: 'lazy'` WebRTC negotiates a sendrecv audio transceiver with no sender track and no microphone acquisition or capture. `attachMic()` acquires the app's microphone lease and replaces the sender track; `releaseMic()` replaces it with null, stops capture and releases the lease without renegotiation. Playback routing remains available until stop. Pending microphone operations are serialized and cleaned up on release/close; mute state persists across attachments. Eager WebRTC and PCM remain the defaults. WebRTC caps SDP at 128 KB, data at 32 KB and queued data at 64 KB; each handle owns one peer.

OpenAI reports token usage per completed response, Gemini reports usage metadata, xAI reports elapsed minutes and ChatGPT reports elapsed subscription seconds. No live provider proof is claimed by the offline flow tests. Tests use loopback WS/HTTP and injected media, audio and app ports under the repository's egress guard.

## Interruption and reconnect policy

`client.interrupt()` clears local playback and sends `realtime.control` with `action: interrupt`. Providers fence audio and tool replies until a new response begins. Response ids, where supplied, prevent late old responses from entering a newer turn. A provider disconnect aborts unfinished calls too. No tool, sent speech, or captured microphone packet is replayed after reconnect.

OpenAI, Gemini and xAI retry transient provider disconnects at most twice, after 500 and 1,000 ms. Thirty seconds of ready service restores the budget. Authentication, permission and invalid-protocol failures are terminal. Client transport and WebRTC failures use the same bounded policy; `retryableClose(reason)` lets the app classify transport closures. A normal `realtime.closed` is terminal; only an explicitly retryable close (ChatGPT interrupt rotation) reopens the call. By default each media attempt releases its microphone, route and peer before another acquires them. `preserveMediaOnReconnect` retains ready PCM capture/route and the playback tail across a carrier reconnect, drops capture while disconnected, and releases on stop or before a PCM format change; pending acquisition and WebRTC peers still release before retry. Stop cancels retries. Reconnect creates a new session (Gemini can resume its provider handle); the app supplies any context it wants to restore. `player.finish` false immediately reports connected, and an audio clear flushes queued speech even while muted.
