# Realtime voice lift

The named first consumer is muxr. Version 0.1.0 lifts its four native speech-to-speech routes: ChatGPT subscription voice, OpenAI, Gemini and xAI with an API key (billed per use). ChatGPT is a plain catalogue route, with no feature flag or approval gate. Its terms are labelled as data. Provider selection, prompts, tool authorization and internal identifier masks belong to the app.

The launch decisions supersede the older extraction map: no audio foundation dependency; injected microphone, capture, playback and route ports; every provider adapter runs in a kit-owned child process; ChatGPT uses fresh access from `Accounts.access(member)` and BYOKit's own originator. The kit never reads another tool's login or runs its CLI. Reconnect and new barge-in policy belong to a follow-up change; the lifted adapters retain existing server interruption and retry behavior.

The portable entry exports the bounded `realtime.*` frame vocabulary, parsers, `AudioPorts`, `realtimeClient`, error types, words and provider catalogue. `./webrtc` exports browser WebRTC and a lazily loaded RN peer (the app supplies `react-native-webrtc`). `./node` exports `realtimeEngine`, `toolBridge` and `appBridge`. The initial surface retains the extraction spec’s frame-based seam so the existing carrier can consume the lift directly.

`realtimeEngine` accepts `{ engine, auth, instructions, tools, bridge, emit, model?, voice?, redact? }`. Keys are injected as `{kind:'key', key}`. ChatGPT accepts `{kind:'plan', access: signal => accounts.access(member, signal)}`. The parent resolves access, transfers it only over the child's private stdin, and never puts it on the device stream. The child dials only the selected engine endpoint. Endpoint overrides are limited to loopback fakes. The parent bounds lines and pending input, discards child stderr, redacts credentials and app patterns, and terminates then kills the child on close.

Tool handlers run in the app process. `toolBridge` enforces an allowlist, 16 KB arguments, idempotency per call id, 128 remembered calls, eight active calls, aborts, per-tool watchdogs and 8,000-character results. App wording for tool failure is injected. ChatGPT delegates through the tool named `delegate` with `{request}`; the app supplies its planner. Retransmitted delegation IDs do not re-run, and identical requests in the same provider turn share one result.

`realtimeClient` consumes an app-provided stream and audio ports. It waits for `microphone.acquire()` before capture or WebRTC media, releases on stop, caps pending microphone bytes at 96,000, observes synchronous send admission, emits turns and states, and forwards app request/reply frames. Playback owns drain and output flow control. WebRTC caps SDP at 128 KB, data at 32 KB and queued data at 64 KB; each handle owns one peer.

OpenAI reports token usage per completed response, Gemini reports usage metadata, xAI reports elapsed minutes and ChatGPT reports elapsed subscription seconds. No live provider proof is claimed by the offline flow tests. Tests use loopback WS/HTTP and injected media, audio and app ports under the repository's egress guard.
