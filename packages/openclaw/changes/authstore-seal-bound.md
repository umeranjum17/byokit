- FIX: A large engine home can no longer abort the process at seal time. AuthStore.collect() stays narrowed to credential state (the complete `state` tree plus non-cache `home` paths; tool caches are skipped), and one snapshot is now capped: credential files totaling more than the new exported `SEAL_CAP_BYTES` (128 MiB) reject with exported `AuthStoreSealSizeError` (`code: 'auth-store-seal-size'`, fields `size`, a lower bound at the refusal, and `cap`) from `prepare()`, `start()` and `stop()` before any oversized file is read or its mode changed, leaving `auth-store.sealed` and the live trees' contents unchanged; a refused `stop()` still releases the lock so a later `start()` works. The seal path also builds its payload once: `@byokit/secrets` encrypt() now emits the same authenticated envelope through bounded chunk-wise escaping instead of a second full-size `JSON.stringify`, so sealing holds one snapshot-sized string, not two. The README's include rule replaces the former "auth-store seal size demand" known limitation.
