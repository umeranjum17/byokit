- FIX: A large engine home can no longer abort the process at seal time. AuthStore.collect() stays narrowed to credential state (the complete `state` tree plus non-cache `home` paths; tool caches are skipped), and saved sign-in data is capped: over the fixed limit, `prepare()`, `start()`, `stop()` and an engine exit reject with exported `AuthStoreSealSizeError` (`code: 'auth-store-seal-size'`, fields `size`, a lower bound at the refusal, and `cap`). On that refusal the last good saved store is kept as it was and no live file is deleted; nothing else is promised. The kit reports `{ phase: 'failed', why: 'auth-store-seal-size', sealSize }` with words giving the size and limit in MB, and a refused `stop()` still releases the lock. `@byokit/secrets` encrypt() also emits its envelope through bounded chunk-wise escaping instead of a second full-size `JSON.stringify`, so the envelope step holds one snapshot-sized string, not two. The README's include rule replaces the former "auth-store seal size demand" known limitation.
