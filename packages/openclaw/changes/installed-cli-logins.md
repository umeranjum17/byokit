- FIX: The engine now uses the person's own Claude and Codex subscription sign-in. The gateway, doctor and its agent CLIs (Claude Code, Codex and the rest) run with the person's `HOME`, plus the person's own `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME` and `XDG_STATE_HOME` when set, instead of a kit-owned home, so an installed, signed-in Claude Code or Codex works with no sign-in step. HOME is not an access boundary: engine processes run with the person's own account rights. The phone-started Claude sign-in stays as the fallback: only when the installed `claude auth status --json` is not signed in does a start point `CLAUDE_CONFIG_DIR` at the engine's own folder (`<stateDir>/openclaw/home/.claude`), as before.
- `doctorContext().env.HOME` is now the person's home; the engine's own home is `OPENCLAW_HOME` (`<stateDir>/openclaw/home`), which is also the gateway's working directory. Engine state, config, cache, tmp, token and bridge socket stay in the state directory.
