- FIX: The Boat adapter's 429/5xx retry backoff ends at once when the caller's abort signal fires, and one 10 s deadline bounds the backoff waits and when a new attempt may start, instead of a per-attempt one. The deadline is per request: one request with all its attempts and waits, so a method that sends several requests gets one deadline each. `boat()` takes an optional `signal` that cancels the provider for good (build a new `boat()` for the next operation); an aborted backoff fails `unreachable`, the same typed error an aborted fetch gives, so a caller checking its own aborted signal keeps reading cancel exactly as before. Past the deadline the last answer stands, exactly as when the retries run out (`provider`, or `unknown` from `status`). The retry counts and the 1 s, 2 s, 4 s waits are unchanged; an in-flight request is never cut, because a non-detached exec POST legitimately stays open up to its `timeoutSeconds`.
