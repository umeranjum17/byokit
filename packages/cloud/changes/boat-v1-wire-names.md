- FIX: The Boat adapter now speaks the public boat-v1 API instead of the loopback fixture's names. It reads the account id at `user.id`, the created/queried sandbox at `sandbox.id`/`sandbox.state`, the deletion operation at `operation.id`/`operation.status === 'completed'`, a detached command's `processId` and `running`, and a named snapshot's `snapshot.status`; it sends `X-Ascii-Confirm-Delete` and `encoding: 'base64'`; its trial plan maps `sandboxPlanKey: 'trial'`/`subscriptionTrialEndsAt`; and `key`/`why` are absent because the public API has no current-key route and no sandbox stop-reason field. The loopback bench (`src/testing/fake-sandbox-server.ts`) now serves those same public shapes. Adapter and fixture only; no live call, no VM, no spend. It also no longer reports a lost or signal-killed command (`status: 'lost'`, null `exitCode`) as exit 0; that read is a `provider` failure. `sleep` polls the sandbox until it is archived, and the deletion and named-snapshot polls are bounded by a typed `timeout`, with a `blocked` deletion treated as terminal.
