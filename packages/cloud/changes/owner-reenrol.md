- FEATURE: A reinstalled app or a new phone can take over its own cloud computer. `setup()` on a computer that already runs the app's own install now ends `failed` with the typed cause `error.ownerEnrolled` (new words that say the person can move it to this phone, and the other phone loses access) instead of the generic `error.app`, and changes nothing. After the person confirms, the same `setup()` with `replaceOwner: true` reinstalls in place (`Machine.adopt` gains `replaceOwner`, which takes over only the kit's own install) and the pair gate gets `{ replaceOwner: true }`, so `pairEnrol`/`deliverPhoneKey` deliver the key as `OWNER_KEY_FILE` (`owner.bin`). On the machine, `replacePhoneKey(host, key)` revokes every other phone grant and binds the new key in one call, durable across restarts. New `MachineErrorCode` `owner-enrolled`; `bindPhoneKey` now rejects with it (was `exists`) when another phone holds the binding.
- SECURITY: Only the provider account can replace the owner phone: the new key arrives only by provider delivery (account key) after the person confirms on the setup device, the host calls `replacePhoneKey` for `owner.bin` only, never for anything a paired device or the network sent, and a `phone.bin` delivery still never replaces an owner. The old phone's grant is revoked before the new key is bound, so a lost phone loses access as soon as its owner re-enrols.
