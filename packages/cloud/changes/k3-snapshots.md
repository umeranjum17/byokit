- FEATURE: Saved copies, reset and disk space for the cloud computer (spec 4.4, 5.10). `snapshots()` lists the kit's own saved copies of the machine, newest first; `snapshot({ keep })` saves one and, only after the provider lists it ready, deletes the oldest of this machine's copies past `keep` (a failed delete is reported as `pruneError` on the saved copy, not thrown) (default 3, inside Boat's 10 free copies; a copy the kit did not make is never touched); `scheduleSnapshots({ everyMs, keep, onResult })` saves a copy when the newest is older than `everyMs`, on a timer while the app runs (returns `{ stop() }`; no hosted scheduler; each check follows the previous one, so a daily schedule saves daily); `restore(id)` rebuilds the machine from one copy as a new machine with the same name and tailnet identity, saves the new ref before the old machine is deleted (a replacement that never comes on is deleted; an old machine that will not delete is retried, then reported as possibly billing), and rejects the typed `no-snapshot` for a copy that is gone; `disk()` reads `{ usedGb, totalGb }` from `df` on the machine. New words `snapshot.restore` (says what a reset loses), `disk.used` and `error.noSnapshot`. Boat implements it; the SSH VM adapter and a machine made with `keepCopies: false` reject `unsupported`. The loopback Boat bench now copies files into a named snapshot and restores them on a create `from` it.
