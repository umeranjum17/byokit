# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Checks: in a fresh checkout or worktree run `npm ci` once first (deps are not inherited; without it `check` fails on missing modules), then `npm run build` (tsc -b per package), `npm run check` (tsc over sources and tests) and `npm test` (`scripts/test.sh`: node:test in a throwaway HOME, then a byte-for-byte check of the real `~/.pi`). CI runs all three on Node 22 and 24. Tests never need an account, the network or a model: `mockOpenAI()` (`packages/accounts/src/testing/mock-openai.ts`) stands in for OpenAI's sign-in, and `scripts/test.sh` enforces the no-network side (`scripts/test-egress-guard.cjs` blocks every non-loopback connect and datagram in every node of the run; loopback fakes and Unix sockets stay allowed).
- The TypeScript packages are the product on Node/Electron, browsers/PWA and React Native (iOS, Android). Keep `@byokit/accounts`' browser and React Native export free of runtime Node/Pi imports (`packages/accounts/test/portable.test.ts`); the same holds for `@byokit/link`'s and `@byokit/decide`'s main entries (their `test/react-native.test.ts`). Platform usage is in each package README; checks, including the Android emulator run `examples/expo/e2e-android.sh`, in `CONTRIBUTING.md`.
- Never touch the owner's installed Pi, `~/.pi`, logins, Herdr, muxr or CLIs, in code or tests. Isolation tests use `packages/accounts/src/testing` (decoy HOME, fs tracer, canaries) and Node's `--permission`; see `packages/accounts/test/isolation.test.ts`.
- Sources are TypeScript run directly by Node (type stripping): `erasableSyntaxOnly` is on, so no enums, namespaces or parameter properties (writing one fails `npm run check` with TS1294); relative imports carry `.ts`, rewritten by tsc on build. JSON data (`catalogue.json`, `words.json`) is imported with `with { type: 'json' }`.
- `@earendil-works/pi-ai` is pinned exactly in `packages/accounts/package.json`; bump only with the isolation test green. Provider terms are data in `catalogue.json`; Anthropic Messages uses an app-passed API key (billed per use), with explicit opt-in.
- `fixtures/README.md` owns conformance scope (including the frozen Kotlin mirror's exception); `packages/accounts/src/{catalogue,words}.json` is the shared data the Kotlin build bundles. Change a rule in the fixture first.
- `android/` is its own Gradle project (byokit-android, the Kotlin mirror, frozen: React Native apps use the TypeScript kit): `android/test.sh [serial]` runs its tests in a throwaway HOME (JDK 17+ in `JAVA_HOME`, `ANDROID_HOME`); CI's `android` job runs it without a device.
- `@byokit/reach` tests run a fake tailscale CLI (`bin` option, PATH set to the fake's dir), a fake mDNS publisher, and a fake zeroconf for the React Native browse API (`src/browse.ts`, injectable; `src/rn.ts` is the only file importing the exact-pinned `react-native-zeroconf` dependency); never the real binary or network.
- `@byokit/decide` never reads an environment variable: the host passes Jev's key to `jev({ key })`; only `byokit-eval --live` reads `TYPESAFE_API_KEY`/`OPENROUTER_API_KEY`. Tests mock `fetch`; eval files replay answers offline.
- Runtime kits `@byokit/openclaw` and `@byokit/herdr` (the aggregator owns subscriptions; `@byokit/accounts` stays for direct-provider apps) are built from `docs/runtime-kits.md`: its decisions, module seams and work packages are binding; a signature or decision change is a spec change first. The pinned engine treats a non-empty `plugins.allow` as a restrictive allowlist, so the kit merges every offered route's `Route.plugin` with the bridge and caller-provided ids (2026.8.1: `openai` for ChatGPT); 5.6 owns that rule, and apps allow any unoffered route they explicitly use.
- Publishing: only from merged main; `npm run release` (scripts/release.ts) owns versions, the dependent cascade, gates, tags and GitHub releases; `release.yml` runs its publish step with OIDC provenance; `private: true` holds a package back. Changes to published package code bump its version. `@byokit/link`'s muxr parity is tracked separately (parity tests name their checklist row, e.g. `R4:`). `@byokit/link/node` is its only Node-only entry. Its crypto deps are pinned exactly, and its browser tests need Chrome/Chromium (Playwright's, else the system's; skipped locally without one, required in CI). `@byokit/relay` depends on link.
