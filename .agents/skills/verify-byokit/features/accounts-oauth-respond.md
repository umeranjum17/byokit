# OAuth subscription account respond

A consumer app with two signed-in Grok accounts (device code) asks `Accounts.respond(member, { account, model, context, onText })` and each answer streams through the pinned Pi Models path with that account's own sign-in; a 429 rests only that account, typed and never retried, while the other still answers; a refresh the provider proves revoked (`invalid_grant`) or refuses with a bare 400-403 signs only that account out, while a 5xx or a dropped connection keeps the sign-in, typed `network`; a model from another provider and a route the platform cannot run are refused, typed, before any request. All against the built `@byokit/accounts` (`.`, `/keys`, `/testing`), `mockDevice()` and a loopback stand-in for xAI's Responses endpoint that replays `fixtures/conformance/pi-streams.json`. The same path serves GitHub Copilot, Kimi and Meta sign-ins.

## Sub-features

- `oauth-respond-own-bearer`: `respond` for the bare primary `grok` and for `grok.<id>` each streams the fixture answer (`Hello` into `onText`, the `lookup` tool call, usage `[3, 2, 5]`, `stopReason: 'toolUse'`), and the request reaching `/v1/responses` carries that account's own bearer.
- `oauth-respond-429`: a 429 (with `retry-after: 120`) on `grok.<id>` rejects with `ResponseError` kind `rate_limit`, `status` 429 and `until` about two minutes out; exactly one request went out; `status` shows that account `resting` and the primary `ready`, and the primary still answers.
- `oauth-respond-provider`: a model whose `provider` is not `xai` rejects with `KeyRouteError` code `provider` before any request.
- `oauth-respond-not-included`: Meta's route (`meta:code`, browser `no`) on `withKeys(portable)` rejects with `ResponseError` kind `not_included` before any request, where it used to throw an untyped `Error`.
- `oauth-respond-refused-refresh`: once the primary's sign-in is due and the provider refuses its refresh (`invalid_grant`, 400), `respond` rejects with `ResponseError` kind `signed_out`, sends no request, deletes only that sign-in, and `list` then holds only the other account, still `resting`.
- `oauth-respond-bare-403`: once a fresh sign-in is due and its refresh is answered with a bare 403 and no `invalid_grant` body, `respond` rejects with `ResponseError` kind `signed_out`, sends no request, and deletes that sign-in.
- `oauth-respond-refusal-kept`: once a fresh sign-in is due and its refresh is answered with a 5xx, and again with a dropped connection, `respond` rejects with `ResponseError` kind `network` and that sign-in stays listed.
- `oauth-respond-no-token`: neither access token appears in an answer, event, error, `list`, `status` or the store index.

## How to get to it (user POV)

- The app constructs `new Accounts({ deviceBase, offer: ['grok', 'meta'], store }, withKeys(portable))` with `withKeys` from `@byokit/accounts/keys`, signs in two Grok accounts through `add(1, 'grok', { via: 'code' })` and `finished`, and calls `respond(1, { account, model, context, onText })` with a pinned Pi `Model` whose `provider` is `xai`.

## Driving it with node scratch consumers

Preconditions: baseline (features/README.md); no process of a previous drive is running.

- **Write the consumer.** Create `"$scratch_dir/verify-oauth-respond.mjs"` importing `Accounts, KeyRouteError, ResponseError, portable, recordStore` from `@byokit/accounts`, `withKeys` from `@byokit/accounts/keys` and `mockDevice` from `@byokit/accounts/testing`. Start `mockDevice()` and a `node:http` server on `127.0.0.1:0` that records each request's path and bearer, answers a bearer in its `limited` set with `429`, `retry-after: 120` and a JSON body echoing the bearer, and otherwise replays the `responses` family of `fixtures/conformance/pi-streams.json` as named SSE. Also start a device-base stand-in in front of the mock that forwards every request to it except a refresh (`grant_type=refresh_token`), which it answers with a configured bare status or a dropped connection; hand it to `Accounts` as `deviceBase`. Sign in two accounts (`add`, `mock.approve(signIn.code)`, `finished`, `view(...).id`), read each access with `(await accounts.runtime(1, id)).readCredential('xai')` into a variable (never printed), then print: the two ids; for each, the joined `onText`, `stopReason`, usage, the tool name, and whether the last request's bearer equals that account's own; after adding the second account's access to `limited`, the caught error's class, `kind`, `status`, `until - Date.now()` in seconds, the request delta, both `status(...).state` values and that the primary still answers; the caught `KeyRouteError` `code` for a model with `provider: 'openai'`; the caught `ResponseError` `kind` for `account: 'meta'`; then `store.modify('xai', (c) => ({ ...c, expires: 0 }))` and `mock.state.live.clear()`, and print the caught `kind`, the request delta, whether `store.read('xai')` is gone and `list(1)` as id=state; then sign in a third account and, with the device-base stand-in answering a 500, a dropped connection and a bare 403 on its refresh in turn (making it due each time), print each caught `kind`, the request delta and whether that sign-in is still listed; finally print whether either access appears in the `JSON.stringify` of every answer, event, error, `list`, `status` and the index. Close every server in a `finally`.
- **Run and capture.** `feature=accounts-oauth-respond; entry=@byokit/accounts, @byokit/accounts/keys, @byokit/accounts/testing; drive=(node "$scratch_dir/verify-oauth-respond.mjs")`, then run SKILL.md Evidence's capture block. Exit code `0`.
- **Happy path shows.** `ids: grok,grok.<id>`; for each `text: Hello stop: toolUse usage: 3,2,5 tool: lookup own-bearer: true`.
- **Rest and error cases show.** `429: ResponseError rate_limit status: 429 until-s: ~120 requests: +1`; `states after 429: grok=ready grok.<id>=resting primary-answers: true`; `provider: KeyRouteError provider`; `meta: ResponseError not_included`; `refused refresh: signed_out requests: +0 gone: true list: grok.<id>=resting`; `bare 403 refresh: signed_out requests: +0 gone: true`; `5xx refresh: network listed: true`; `dropped refresh: network listed: true`; `token-leaked: false`.
- **Proof.** The captured artifact contains command output for the action and resulting state of every sub-feature above. The journey test `packages/accounts/test/journey-oauth-respond.test.ts` asserts the same under `scripts/test.sh` (egress guard on).

## Gotchas

- Use `withKeys(portable)`: on a computer, Pi's own engine signs Grok in against xAI itself, which `mockDevice()` cannot stand in for; the portable engine takes `deviceBase`.
- Meta is offered on a portable platform only when the app names it in `offer`; otherwise `respond` stops earlier with `AI account not offered here`.
- After the primary is signed out, the bare `grok` id resolves to the remaining account, so read the outcome from `list`, not `status(1, 'grok')`.
- `mockDevice()` tokens last an hour, so no refresh happens until the drive makes a sign-in due; a rotating refresh spends its grant, and `state.live.clear()` makes the next one answer `invalid_grant`.
- On phones and in browsers the portable engine gives the access token as the key; Kimi's bearer header and Copilot's per-token base URL are derived by Pi's own engine on a computer.
