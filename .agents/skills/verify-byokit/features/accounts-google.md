# Google Cloud Code Assist sign-in and stand-in (mockGoogle)

On a computer, `@byokit/accounts` signs a person in to Google Cloud Code Assist (the Gemini CLI client) with PKCE: `Accounts.add(member, 'google-gemini-cli:browser')` opens Google's own page, the browser returns to the client's fixed loopback port `:8085`, and `list()` then shows a Gemini account ready with the email from the sign-in; `google-gemini-cli:paste` takes the pasted redirect address instead and opens no listener. After the token exchange and userinfo the sign-in asks Cloud Code Assist for the account's project (`loadCodeAssist`, then `onboardUser` and its operation poll when there is none yet) and keeps the project id as non-secret account metadata on the account row, beside the email, never inside the credential; an account with no project of its own and no allowed tier to onboard ends the sign-in with a typed refusal and keeps nothing (an ineligible free tier beside an existing project still signs in). A signed-in Gemini account answers: `Accounts.respond(member, { account, model, context })` streams through Google's `v1internal:streamGenerateContent` with the account's stored project id, parsed into the pinned Pi stream shape. `logout()` revokes the stored refresh token at Google's own revoke endpoint (`POST oauth2.googleapis.com/revoke`, or the `googleBase` stand-in) and then deletes the local copy whatever Google answers. The `mockGoogle()` stand-in answers the whole protocol offline for both Google clients (`google-gemini-cli` `:8085`, `google-antigravity` `:51121`): PKCE authorize, the loopback callback, the token exchange and refresh, userinfo, sign-out revoke, the Cloud Code Assist `loadCodeAssist`/`onboardUser` project calls, and the `streamGenerateContent` SSE answer plus its 403 tier refusal and 401.

## Sub-features

- `google-pkce`: `authorizeUrl()` builds Google's page with the client's recorded scopes and `access_type=offline`/`prompt=consent`; the stand-in returns `303` to the loopback callback with `code` and `state`, and refuses a non-`S256` challenge.
- `google-exchange`: a `POST /token` with `grant_type=authorization_code` and the matching `code_verifier` answers the recorded token; a wrong verifier is refused.
- `google-refresh`: `grant_type=refresh_token` rotates the recorded grant; after `state.refuse` it answers `invalid_grant`.
- `google-userinfo`: `GET /oauth2/v1/userinfo` answers the recorded email.
- `google-project`: `POST /v1internal:loadCodeAssist` answers a recorded existing project; with `state.provision` it answers `allowedTiers` and `onboardUser` plus its operation poll answer the recorded project; with `state.ineligible` it answers `ineligibleTiers`.
- `google-project-signin`: `Accounts.add(member, 'google-gemini-cli:paste')` discovers the account's project after the token exchange and keeps it as `store.index().accounts[id].project` with no token in the metadata; with `state.provision` the same sign-in goes through `onboardUser` and keeps the provisioned project.
- `google-ineligible`: with `state.ineligible` (no existing project and no `allowedTiers`), the sign-in ends with `view.why === 'notIncluded'` (a typed refusal, not a generic failure) and keeps nothing: `store.read` is undefined, `list()` is empty and the index holds no account metadata. An `ineligibleTiers` answer that still carries an existing `cloudaicompanionProject` keeps the project and signs in (`google-project-signin`).
- `google-signin-browser`: `Accounts.add(member, 'google-gemini-cli:browser')` returns a waiting sign-in whose URL is the client's authorize page; fetching it and following its `location` to `127.0.0.1:8085` completes the sign-in, and `list()` shows the account `ready` with `email`.
- `google-signin-paste`: `Accounts.add(member, 'google-gemini-cli:paste')` returns the same page, opens no loopback listener, and completes when `Accounts.paste()` receives the redirect address.
- `google-busy-port`: with `:8085` already held (by another process or by a second Google sign-in in the same process), the browser sign-in returns at once with its pasted-address view (`via: 'code'`) instead of waiting for the `redirectMs` timer, and its wait then serves the browser return once the port frees; `Accounts.cancel()` closes the listener and keeps nothing.
- `google-logout-revoke`: `Accounts.logout(1, 'google-gemini-cli')` sends the stored refresh token as `token=` to the stand-in's `/revoke` (the `googleBase` host, never `authBase`), the stand-in marks the grant revoked, and the local copy is deleted. A refused revoke (`state.refuseRevoke`) still deletes locally and rejects with `Google sign-out failed (400)`, with the token absent from the message and every captured log.
- `google-respond`: `Accounts.respond(member, { account, model, context })` for a signed-in Gemini account POSTs `{googleBase}/v1internal:streamGenerateContent?alt=sse` with the account's stored project id and access token, and returns the pinned Pi `AssistantMessage` (text, usage, `stopReason`) while streaming each delta through `onText`. A 403 tier refusal (`state.tierRefusal`) is the typed `ResponseError` kind `not_included` and marks the account `not_included`; a 401 (`state.unauthorized`) refreshes the sign-in exactly once through the existing Google refresh path and retries, and a second 401 reports the account signed out (`CodeAssistSignedOutError`, kind `signed_out`) and deletes the local copy. The access token is only ever the request's bearer header, never in an event, error or log. Auto picks the account because its billing is subscription.

## How to get to it (user POV)

- On a computer, an app calls `new Accounts({ store, googleBase })` from `@byokit/accounts` and `add(member, 'google-gemini-cli:browser')` (or `:paste`); it shows `signIn.url` to open, then `list(member)` shows the account. `mockGoogle()` from `@byokit/accounts/testing` is the offline stand-in for that page and every endpoint.

## Driving it with node scratch consumers

Preconditions: baseline (features/README.md); no process of a previous drive is running; `:8085` free.

- **Write the consumer.** Create `"$scratch_dir/verify-google.mjs"` importing `Accounts`, `memoryStore` from `@byokit/accounts` and `mockGoogle` from `@byokit/accounts/testing`. Part A, the stand-in, for each of `google-gemini-cli` and `google-antigravity`: start the mock, build a PKCE verifier/challenge, `fetch(mock.authorizeUrl({ redirectUri, state, codeChallenge }), { redirect: 'manual' })` and follow the `location` to the loopback callback; exchange the code, read userinfo, call `loadCodeAssist` (existing project, then `provision` for onboard + poll), refresh, then set `state.refuse`/`state.ineligible` and print each `invalid_grant` and `ineligibleTiers` answer; close it. Part B, the sign-in, on a fresh mock and `new Accounts({ store: () => memoryStore(), googleBase: mock.base, app: 'verify' })`: (1) `add(1, 'google-gemini-cli:browser')`, `fetch(signIn.url, { redirect: 'manual' })`, `fetch(location)`, `finished`, print `list(1)` (provider, state, email) and the refresh answer from `runtime(1).getAuth('google-gemini-cli', { minOAuthValidityMs: 10**9 })`, then `logout(1, 'google-gemini-cli')` and print `state.revoked` and the `/revoke` request body (the stored refresh token) plus that the store and `list(1)` are empty; set `state.refuseRevoke = true`, sign in again, `logout` and print the caught `Google sign-out failed (400)` with the store still deleted and no token in the message; (2) `add(1, 'google-gemini-cli:paste')`, `paste(1, id, location)`, `finished`, print `list(1)`; (3) hold `:8085` with a foreign `createServer`, `add` browser, print that it returns at once with `via: 'code'`, then free the port and print the same redirect address answered `200` and `list(1)` ready (the wait still serves the browser return); (4) start a browser `add(1, …)` that holds `:8085`, then `add(2, …)` and print the second's `via: 'code'` at once, paste its redirect address, and print `list(2)` ready; (5) `add` browser then `cancel`, print that the store and `list` are empty. Print whether `recorded-access`/`recorded-refresh` appear in `list`/`status`/the index, then close the mock.
- **Project discovery legs (Part C).** On a fresh mock, `new Accounts({ store: () => memoryStore(), googleBase: mock.base, app: 'verify' })`: (1) eligible — `add(1, 'google-gemini-cli:paste')`, `paste(1, id, location)`, `finished`, then print `list(1)[0].id` and `store.index().accounts[that id].project` (`recorded-project`), that `JSON.stringify` of that metadata holds no `recorded-access`/`recorded-refresh`, and that the stored credential carries no `project`; (2) provision — set `state.provision = true`, sign in the same way, print the kept `recorded-project` and the recorded `POST /v1internal:onboardUser` and `GET /v1internal/operations/recorded-onboard` requests; (3) ineligible — set `state.ineligible = true`, sign in, print `view(1, id).state`/`.why` (`failed`/`notIncluded`), that `store.read('google-gemini-cli')` is undefined, `list(1)` is empty and the index holds no account metadata; (4) existing project beside an ineligible tier — sign in with a `fetch` wrapper that answers any URL containing `/v1internal:loadCodeAssist` with `{ cloudaicompanionProject: 'recorded-project', ineligibleTiers: [{ tierId: 'free-tier' }] }` and otherwise delegates to the real fetch, and print `list(1)` ready with the kept `recorded-project` and no `onboardUser` request. Reset the switches between legs.
- **Respond legs (Part D).** On a fresh mock per leg, `new Accounts({ store: () => memoryStore(), googleBase: mock.base, app: 'verify' })`: sign in with `:paste` (the sign-in keeps the account's `recorded-project` as index metadata), then (1) `respond(1, { account: id, model, context, onText })` and print the joined text, the deltas, `usage`, `stopReason`, and the request body's `project`/`model`; (2) `state.tierRefusal = true`, `respond` and print the caught error's `kind` and message plus `status(1, account).state`; (3) `state.frameDelayMs = 30`, `respond` and print that the first `onText` delta arrives before the promise resolves (streamed, not buffered) plus the deltas; (4) `state.unauthorized = 1`, `respond` and print `stopReason` and the counts of `/token` refresh and `/v1internal:streamGenerateContent` requests; (5) `state.unauthorized = 2`, `respond` and print the caught `signed_out` error, the refresh count, and that the store and `signedIn` are empty. Assert the token never appears in any error message.
- **Run and capture.** `feature=accounts-google; entry=@byokit/accounts, @byokit/accounts/testing; drive=(node "$scratch_dir/verify-google.mjs")`, then run SKILL.md Evidence's capture block. Exit code `0`.
- **Happy path shows.** For both clients the recorded `access_token`/`refresh_token`, the recorded `email`, the existing `recorded-project` and the provisioned `recorded-project`; for the sign-in, a `ready` row with `umer@example.com` and `rotated-access` after the refresh; for sign-out, the `/revoke` request carrying the stored refresh token and `state.revoked` holding it; for respond, the streamed `Hello world` in two deltas with usage `[3, 2, 5]`, `stopReason: 'stop'`, and the request body carrying `project: 'recorded-project'`.
- **Error case shows.** The `400 invalid_grant` on a refused or reused refresh, the `ineligibleTiers` answer for an individual account with no Code Assist tier, a refused refresh at `getAuth` with no token in the error, and a refused revoke (`state.refuseRevoke`) that still deletes locally, rejects with `Google sign-out failed (400)` and leaks no token; for respond, a 403 as the typed `not_included` error (and `status` `not_included`), and a second 401 as `signed_out` after exactly one refresh, with the token absent from every message and the local copy deleted.
- **Proof.** The captured artifact contains command output for the action and resulting state of every sub-feature above.

## Gotchas

- The stand-in answers on an OS-assigned loopback port; the client's real callback port (`8085`, `51121`) is a recorded fact in `mock.protocol.callback`, not a port the mock binds.
- It records no client secret: the authorize URL uses the client's public id, and `fixtures/conformance/google-oauth-typescript.json` names the reuse rule without any secret.
- `state.provision` and `state.ineligible` are switches for the two project outcomes; reset them between calls.
- `google-antigravity` is a data-only client here; its routes land in WP6-S5. The sign-in flow is `google-gemini-cli` only.
- The respond adapter reads the account's Code Assist project from non-secret metadata (`index.accounts[id].project`), which the sign-in stores; `state.frameDelayMs` makes the stand-in space the streamed frames so a consumer can prove each delta lands before the answer ends.
