# Catalogue device sign-in and the picker

A consumer app offers the person every provider the accounts catalogue can sign in to on this device, picks one, and completes its RFC 8628 device sign-in: the code appears, the person approves it on their own phone, and the sign-in lands in that member's store — all against a loopback stand-in, with no provider of its own in the code.

## Sub-features

- `device-picker`: `accounts.providers` (and `signInChoices()`) list every provider the device can sign in to, in catalogue order; a provider joins by catalogue `device` data alone. Called with the app's own `offer` list, `signInChoices(offer)` includes a provider it names even when the catalogue keeps it explicit (`offer: false`, e.g. MiniMax) and leaves out one it does not name; called with no argument it keeps the catalogue's default rows.
- `device-signin`: `login` shows a waiting device code and the provider's page; approving the code there finishes the sign-in and `status` reads `ready`.
- `device-minimax`: `login(member, 'minimax')` (or `add(member, 'minimax:code')`, with `offer` naming `minimax`) drives MiniMax's user-code flow (`mockDevice({ dialect: 'minimax' })`): PKCE, a `user_code` grant and a status-field token body; `minimax:code:cn` shows the `account.minimaxi.com` page, and `add(member, 'minimax:code:cn')` selects the China host. A declined or expired user code keeps nothing and says so in one sentence.
- `device-refresh`: a token that dies is refreshed on the provider's own token endpoint, so `status` stays `ready`.
- `device-kept-grant`: a provider that keeps its grant (answers a refresh with no new refresh token, `mockDevice({ rotate: false })`) stays `ready` refresh after refresh; a revoked grant still ends at `needs_again`.
- `device-declined`: declining on the provider's page keeps nothing and says so in one sentence.
- `device-copilot`: `login(member, 'copilot')` on the portable entry shows the device code and the `github.com/login/device` page (`mockDevice({ dialect: 'copilot' })`); approving it signs in through the catalogue's second exchange (`GET api.github.com/copilot_internal/v2/token` with the intermediate GitHub token as `Authorization: Bearer`), `list()` reads Copilot ready, and `keepFresh` re-mints with that same GET from the stored intermediate. A declined code keeps nothing and says so in one sentence; a 401 or 403 on the exchange is a refused grant (signed out once, never retried). An enterprise domain is refused before any store is read (phones sign in on github.com only). The kept credential carries only the exchanged token and the intermediate; neither token appears in `list`, `status`, the index or an error. Fixture: `fixtures/conformance/device-code-rfc8628-typescript.json` (the stand-in replays it for `github.com` and an Enterprise host; the runtime journey is github.com).

## How to get to it (user POV)

- The consumer app constructs `new Accounts({ deviceBase, store: () => memoryStore() }, portable)` against `mockDevice()`'s base, reads `accounts.providers`, calls `login(1, key)` for the chosen one, shows `view.code`/`view.url`, and the person approves at the provider's page; then `finished`, `status`, `keepFresh`, `logout`.

- **Write the consumer.** Create `"$scratch_dir/verify-accounts-device.mjs"` importing `Accounts, memoryStore, portable, signInChoices` from `@byokit/accounts` and `mockDevice` from `@byokit/accounts/testing`. Print the picker: `signInChoices().map((p) => p.key)` (the catalogue default) and `signInChoices(['minimax']).map((p) => p.key)` (an app that names MiniMax). Sign in with `grok` and with `kimi` (approve each code at the stand-in), print `status` for each, run `keepFresh` and print the refresh request the stand-in saw; repeat the sign-ins against `mockDevice({ expiresIn: 1, rotate: false })`, run `keepFresh` three times and print each `status`; then clear `device.state.live` (the provider revokes) and print `status` after one more `keepFresh`; then start one sign-in and decline it, printing `view().error`. Then sign in with MiniMax: start `mockDevice({ dialect: 'minimax' })`, `login(1, 'minimax')`, print `view().code`/`view().url`, approve, print `status`; repeat with `add(1, 'minimax:code:cn')` against `mockDevice({ dialect: 'minimax', region: 'cn' })` and print the shown page host; then decline one MiniMax sign-in and print its one-sentence error. Then sign in with Copilot against `mockDevice({ dialect: 'copilot' })`: `login(1, 'copilot')`, print `view().code`/`view().url` (the code and the `https://github.com/login/device` page), approve, print `status` and the `list()` row; expire the kept credential through the member's own store and run `keepFresh`, printing the re-mint `GET /copilot_internal/v2/token` the stand-in saw and the `status` after it; print only the kept credential's key names (the grant's extra fields stay out) and masked tokens (first 4/last 4/length, never the values); decline one Copilot sign-in and print its one-sentence error with nothing stored; refuse the exchange (`state.refuse = true`, 401) and print `status` after two `keepFresh` runs (signed out once); then pass an enterprise domain and a malformed domain to `login` and print each refusal. Print the stand-in requests as `METHOD path grant` lines only (never bodies or headers). Call `await device.close()` (and each stand-in's `close()`) at the end.
- **Run and capture.** `feature=accounts-device; entry=@byokit/accounts; drive=(node --conditions=react-native "$scratch_dir/verify-accounts-device.mjs")`, then run SKILL.md Evidence's capture block. Exit code `0`. The condition imports the built portable entry (`dist/portable.js`); this is Node running the React-Native export condition, not an Android/iOS device, emulator or physical phone, and no live vendor is touched.
- **Happy path shows.** `picker: grok,copilot,kimi` and `picker (app offer): minimax` (the catalogue default leaves MiniMax out; an app that names it gets it), a `FIXTURE-` code with the stand-in's `/activate` page for each provider, `status: ready` for both, a `grant_type=refresh_token` request, and `ready` after every refresh from the kept-grant stand-in. MiniMax: `login code: FIXTURE-MINIMAX-CODE`, `login page: https://account.minimax.io/activate`, `status: ready`, the cn route's page on `https://account.minimaxi.com/activate`. Copilot: `login code: FIXTURE-COPILOT-CODE`, `login page: https://github.com/login/device`, `status: ready`, `list: copilot/subscription/ready`, one added re-mint `GET /copilot_internal/v2/token` after `keepFresh`, and kept-credential keys exactly `access,expires,refresh,type` at sign-in (the store's own refresh marker joins after a re-mint).

## Gotchas

- `deviceBase` replaces each provider's own host while keeping its documented paths, so the stand-in answers `/oauth2/device/code` and `/oauth2/token` as well as Kimi's.
- The stand-in rotates the refresh token on every answer by default; `rotate: false` keeps the grant live and answers refresh with a new access token only.
- The explicit `memoryStore()` keeps sign-ins in memory, so a declined or cancelled sign-in leaves nothing behind for anyone.
- `signInChoices()` is catalogue data only: no network, no credentials, no readiness claim. Its optional argument is the app's own `offer` list (the same `readonly string[]` as `offered` and `AccountsOptions.offer`), not a platform or readiness check.
