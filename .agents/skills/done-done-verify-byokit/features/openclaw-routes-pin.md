# OpenClaw route table describes the pinned engine

The built `@byokit/openclaw` carries the generated route table (`src/routes.json`). Every row's `source` and `revision` name the engine the kit pins (`ENGINE_VERSION`), because discovery that names an older pin would offer a choice the real Gateway refuses (or hide one it has). `kit.routes()` is pure kit data — it answers without an engine, so the drive starts a kit against the loopback fake and reads the table. `readiness` still reflects real dependencies: a choice whose plugin is not bundled reports `needs_plugin`, a compatibility alias reports `no_upstream_flow`.

## Sub-features

- The table is generated by `packages/openclaw/scripts/gen-routes.ts` from the pin named by `PIN`, which must equal `ENGINE_VERSION`; the public-API journey test in `packages/openclaw/test/signin.test.ts` fails whenever the table names anything else.
- `routes(facts)` readiness ladder (`needs_plugin`, `no_upstream_flow`, `needs_binary`, …) is unchanged by a pin rebuild; only the pin metadata moves.

## How to get to it (user POV)

A host app lists the kit's discovery: every sign-in choice with its billing and readiness, and why a row waits (`needs_plugin zai`, an alias the Gateway does not offer). A stale table would say the wrong engine has (or lacks) a choice.

## Driving it with a node scratch consumer

From the worktree root, after `npm run build` (see the parent skill), a plain consumer imports the built public entry and its testing fake:

```js
import { join } from 'node:path';
import { rmSync, mkdtempSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { createRequire } from 'node:module';
import { OpenClawKit } from '@byokit/openclaw';
import { fakeGateway } from '@byokit/openclaw/testing';

const require = createRequire(import.meta.url);
console.log('resolved ->', require.resolve('@byokit/openclaw')); // must be packages/openclaw/dist/index.js

const PIN = '2026.9.33';
const stateDir = mkdtempSync(join(tmpdir(), 'byokit-routes-pin-'));
const kit = new OpenClawKit({ stateDir, transport: fakeGateway().factory, spawnEngine: false });
try {
  await kit.start();
  const all = kit.routes();
  if (!all.length) throw new Error('routes() returned nothing');
  const stale = all.filter((r) => !(r.source.includes(PIN) && r.revision === PIN));
  if (stale.length) throw new Error(`rows not from the pinned engine: ${stale.map((r) => r.choice).join(', ')}`);
  const offered = all.filter((r) => r.offer).map((r) => `${r.choice}:${r.via}`);
  if (!offered.some((o) => o.startsWith('openai:'))) throw new Error('the ChatGPT plan row is not offered');
  console.log(`routes -> ${all.length} rows, all ${PIN}; offered: ${offered.join(', ')}`);
  const plugin = all.find((r) => r.readiness === 'needs_plugin');
  if (!plugin) throw new Error('no needs_plugin row');
  console.log(`needs_plugin -> ${plugin.choice}: ${plugin.why}`);
  const absent = all.find((r) => r.readiness === 'no_upstream_flow');
  if (!absent) throw new Error('no no_upstream_flow row');
  console.log(`no_upstream_flow -> ${absent.choice}: ${absent.why}`);
  console.log('DRIVE OK');
} finally {
  await kit.stop().catch(() => {});
  rmSync(stateDir, { recursive: true, force: true });
}
```

Extreme cases: a row whose plugin the pin does not bundle reports `needs_plugin` with the plugin id (discovery never installs it), and a compatibility alias reports `no_upstream_flow` instead of posing as a sign-in. The resolved path must be inside `packages/openclaw/dist`, never a registry copy.

## Gotchas

- The pin lives in two places that must agree: `ENGINE_VERSION` (the kit) and `PIN` (the generator). The journey test ties them; a drift redden it before any app sees a wrong row.
- `offer` is legacy eligibility; `offerPolicy` is the data. Rebuilds of the same pin change neither.
