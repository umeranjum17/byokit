# Cloud phone-key enrol (K-ENROL, K-RECEIPT, K-PUBLIC)

The setup device hands exactly the one authenticated phone's 32-byte public key to the machine through provider delivery, and the machine's host process binds it with `Host.enrol` from the built `@byokit/cloud`. No new pairing crypto; the key travels only as delivery bytes, never in `run.env`, `run.argv`, logs or error text. The host answers with a receipt of public values (`phoneReceipt`, outbox `receipt.json`); `setup()` secures the SSH route first (`securing`: the pinned host key, a listener on the machine's loopback, one forward that opens; no tailnet) and the `pairing` step carries `receipt: { host, device, urls, ssh }`: with its own SSH transport, that is all the phone needs to open a real `@byokit/pair` link through `sshResolve`.

## Sub-features

- `enrol-bind`: delivery, bind, rebind, `exists` for another key, restart-safe (the node scratch consumer below).
- `pair-receipt-bench`: `capture/cloud-pair-receipt.mjs bench` — fake provider reached through `fakeSshTransport()`, real `Host` in-process on a loopback socket the fake forward carries machine port 7300 to: with nothing listening yet, `failed:securing:state.failed:true` (retryable, no pairing); then steps `checking-access … installing, securing:ssh:7300, pairing:receipt, ready`; one proof forward opened and closed; the receipt's `urls` are `ws://127.0.0.1:7300`, its `ssh` route is pinned and its host key matches; the phone links (`online`) through `sshResolve` with only the receipt and answers one `get.state`; another phone holding the same receipt is refused (`removed`); the only Tailscale-named command is the old-drop-in check.
- `pair-receipt-live`: `capture/cloud-pair-receipt.mjs live` — one real Boat machine: create, install a small pair host from a packed `@byokit/cloud` + `@byokit/pair`, let a throwaway lab SSH key in with `/sshkey` and pin the host key Boat names, `setup()` with `address: { port, transport, publicKey }` (securing over SSH), then this computer links through an SSH forward to `ws://127.0.0.1:7300` on the machine with only the receipt, makes one request, and a stranger phone is refused; no Tailscale on the machine and the public app port refused or dropped. Always deletes the machine and confirms it is gone.

## Driving it with node scratch consumers

Preconditions: baseline (features/README.md). Import public entries only (`@byokit/cloud`, `@byokit/cloud/testing`, `@byokit/pair`); print no key bytes, base64 or grant ids.

- **Write the consumer.** `"$scratch_dir/verify-cloud-phone-enrol.mjs"`: create and install the `web` recipe on `fakeProvider()`, `deliverPhoneKey` the phone key, `Host.open` over an in-memory grant store, `bindPhoneKey` the landed bytes, rebind the same key, refuse another with `owner-enrolled`, reopen the store and repeat. The `setup()` leg is the receipt bench below (`pairEnrol` now waits for the host's receipt).
- **Run and capture.** `feature=cloud-phone-enrol; entry=@byokit/cloud; drive=(node "$scratch_dir/verify-cloud-phone-enrol.mjs")`, then run SKILL.md Evidence's capture block. Exit code `0`.
- **What it proves.** `delivered` is 32 bytes at mode 600 owned by the run user; `bind` is bound with one `control`/`phone` grant matching the key; `rebind` is unbound with the same id; `second-key` is `owner-enrolled`; after reopening the store `restart` still holds one grant, the same key rebinds and another is refused; a 3-byte key is `bad-recipe`.

### Owner re-enrol (K-EXISTS)

A reinstalled app or a new phone (empty store) running `setup()` on its own computer gets `failed` at `inspecting` with cause `error.ownerEnrolled`, `retryable: false`, and nothing on the machine changes; only the same `setup()` with `replaceOwner: true` (after the person confirms) reinstalls in place and delivers the key as `owner.bin`, which the host binds with `replacePhoneKey` and answers with its receipt: the old phone's grant is gone, the new one bound, and a later `phone.bin` of the old key is refused `owner-enrolled`.

- **Bench.** `sh scripts/test.sh packages/cloud/test/enrol.test.ts` (the `a new phone sees the typed owner cause…` journey: fake provider, real `Host` over a durable grant store, reopened for the restart).
- **Live run (boat.dev).** `feature=cloud-owner-reenrol; entry=@byokit/cloud; drive=(node .agents/skills/done-done-verify-byokit/capture/cloud-owner-reenrol.mjs "$boat_key_file" "$tgz")`, where `$boat_key_file` is the fleet's saved Boat key file and `$tgz` is `npm pack` of `packages/cloud` (omit it to install `@byokit/cloud@next` on the machine). Run SKILL.md Evidence's capture block, then `leak_check` the Boat key read into a variable. It creates one `small` sandbox without copies and always deletes it. Pass: `setup-a` ends `pairing:receipt`, `ready` and `host-a` holds phone A; `setup-b` is `failed:inspecting:error.ownerEnrolled:retryable=false` with `unchanged-after-refusal: true`; `setup-b-replace` ends `pairing:receipt`, `ready` and `host-b` holds phone B only; `after-restart` (a newer `started`) still B only; `stale-a-refused` shows `phone.bin:owner-enrolled`; `removed: "gone"`. First passed 2026-10-18. Follow the Boat rule in `cloud-claim.md` (fleet key never printed or revoked, delete only your own machine, no claim).

## Receipt and secure address (maintained capture)

Pack the built kit outside the repo (`npm pack --pack-destination <scratch>` in `packages/cloud`), then run with `BOAT_KEY_FILE=<key file> EVIDENCE_DIR=<outside the repo> CLOUD_TGZ=<scratch>/byokit-cloud-<version>.tgz node .agents/skills/done-done-verify-byokit/capture/cloud-pair-receipt.mjs live`. It makes its own lab SSH key in a temp folder (by path, never printed, deleted at the end), records the machine in `owned.json` before anything else, retries a `securing` that finds the host not yet listening for up to 10 minutes, and ends with `removed`, `still-listed: false`, `status-after: "gone"` and `result`. Pass: `sshaccess.scannedMatches: true`; a round ending `securing:ssh:7300, pairing:receipt, ready`; `request-over-ssh` names the machine; `stranger` is `link refused`; `tailscale-on-machine: "none"`; `public-app-port` is `refused` or `dropped`. Never print the key; the driver's guard throws if it reaches an output line. First passed with SSH reach 2026-10-23.

## Gotchas

- The inbox file is delivery bytes, not a secret: still print only its length, mode and owner, never its content.
- Remove only `"$scratch_dir"` in cleanup; the `.verify-artifacts/cloud-phone-enrol/` evidence survives.
