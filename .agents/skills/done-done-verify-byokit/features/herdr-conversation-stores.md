# Herdr conversation stores

Verify the built `@byokit/herdr` public kit can export Codex and OpenCode history from an explicit account data root, import the bundle into a second root, and return the same bundle digest and native conversation id. Use only synthetic session fixtures in a temporary directory; no CLI, model, network, credentials or default HOME. Codex live session data may be unavailable or protected by the host read guard; report that limitation, do not try another path. The OpenCode host store may likewise be absent or protected.

The fixture journey must write a Codex `sessions/YYYY/MM/DD/rollout-<timestamp>-<uuid>.jsonl` with a `session_meta` record and an earlier user turn. The OpenCode fixture uses `storage/session/<project>/<session-id>.json`, `storage/message/<session-id>/<message-id>.json` and the message's `storage/part/<message-id>/<part-id>.json` text record. Export via an idle agent ref from a stand-in Herdr server, import through `kit.importConversation`, verify all restored records and earlier-turn text, then re-export the imported store and compare `kind`, native `conversation`, `files`, `bytes` and `digest` byte-for-byte with the first export. Include a missing/unsupported-kind refusal. The focused checks are `sh scripts/test.sh packages/herdr/test/conversations-codex.test.ts packages/herdr/test/conversations-opencode.test.ts`.

This proves the real filesystem readers and bundle importer against minimal fixtures, not actual Codex or OpenCode CLI resume. A separate host session capture is only admissible when the harness's own session file can be copied without reading its login/config data; leave originals untouched and never log transcript content.
