# Herdr agent pane under a task-owned HOME

A consumer app starts a Herdr agent pane with `startAgent({ env: { HOME: <task dir> } })` and the agent runs under that home: `HOME` and the XDG config, data, state and cache directories point inside the task directory, so anything the agent writes (or a sign-in inside the pane) stays there. `env: { env, unset }` replaces the whole environment instead. Gemini, which has no managed folder variable, gets its per-account root the same way (packages/herdr/README.md, Account-specific sign-ins and moves).

## Sub-features

- `record-home`: a record env with `HOME` gives the agent process that HOME and XDG dirs under it.
- `launch-home`: a LaunchEnvironment (`{ env, unset }`) leaves the agent only the given variables.
- `inside-view`: a shell inside a pane opened with the HOME env sees the task's marker file and none of the person's agent folders.
- `existing-pane-refused`: a record env on an existing pane is refused with the typed `env_mismatch` error.
- `gemini-record-home`: `openSignInTab` with the README's Gemini env (`HOME`, `GEMINI_CLI_HOME`, `TMPDIR`, `GEMINI_FORCE_FILE_STORAGE`) runs Gemini under that root: its process env points there, its state lands there, and it shows its own sign-in chooser.
- `gemini-folder-refused`: `openSignInTab({ kind: 'gemini', folder })` is refused with the typed `sign_in_failed` error (no managed folder variable).

## How to get to it (user POV)

- The consumer adopts a running Herdr: `new HerdrKit({ mode: 'adopt', bin, socketPath })`, `await kit.start()`, then `kit.startAgent({ kind: 'pi', name, cwd, place: { workspace: 'new' }, env })`, or for an account sign-in `kit.openSignInTab({ workspaceId, kind: 'gemini', name, cwd, env })` (packages/herdr/README.md).

## Driving it with node scratch consumers

Preconditions: baseline (features/README.md); `/usr/bin/herdr` at the pinned version (`herdr --version` prints `herdr 0.9.1`); the `pi` CLI installed (its directory goes on the pane PATH; no sign-in is used); the installed Gemini CLI 0.56.0 bundle's absolute `bundle/gemini.js` (never a mise launcher or shim) and `/usr/bin/node`; and an **isolated, non-default Herdr session** provisioned and torn down by the environment's Herdr lab helper, whose socket path the drive receives as its first argument. Never adopt the person's own Herdr session.

- **Write the consumer.** `"$scratch_dir/verify-herdr-task-home.mjs"` importing `HerdrKit` from `@byokit/herdr`, taking `socketPath`, a fresh task directory, the pi directory and the absolute `gemini.js` as arguments. For `record-home` and `launch-home` it writes `byk-marker` into a per-case home, calls `startAgent` with a distinct `name` per case, finds the agent pid via `kit.call('pane.process_info', …)` (the foreground process that is not the shell) and prints `HOME`, the four `XDG_*` values, `PI_CODING_AGENT_DIR` and the key count from `/proc/<pid>/environ`, plus the task home's entries. For `inside-view` it opens a pane with `kit.call('workspace.create', { cwd, focus: false, env: { HOME } })`, sends `cat "$HOME/byk-marker"` and `test -e` checks for `.pi .claude .codex .config/opencode .gemini` with `pane.send_text`, and prints `kit.read(pane, { source: 'recent_unwrapped' })`. For `existing-pane-refused` it calls `startAgent({ place: { pane: <that pane> }, env: { HOME } })` and prints the caught error's `code` and `message`. For `gemini-record-home` it writes a synthetic `.gemini/settings.json` into a fresh root (usage statistics, update checks and folder trust off; no sign-in method), creates `<root>/.tmp`, puts a runtime-pinning `gemini` shim first on the pane PATH (a one-line `exec /usr/bin/node <gemini.js> "$@"` file under Herdr's launch executable name — no `HERDR_AGENT`; the kit's own hint function carries it, see herdr-agent-hint.md), writes a preload that loads `scripts/test-egress-guard.cjs` and logs every blocked dial or non-loopback lookup, then calls `openSignInTab` into a workspace made with `workspace.create` (cwd a separate folder under the task directory), env = the README recipe plus `PATH`, `NO_BROWSER=true`, a dead `DBUS_SESSION_BUS_ADDRESS` and `NODE_OPTIONS=--require=<preload>`. It prints `agent.get` as the call returns, waits for the chooser in the pane read and prints it, then prints every Gemini process's argv and recipe, `XDG_*` and `HERDR_AGENT` values from `/proc/<pid>/environ`, `agent.get` again (polled until `gemini` and `idle`), the root's tree and the egress count. It never selects a sign-in method. For `gemini-folder-refused` it calls `openSignInTab` with `folder: <root>` and prints the caught error's `code` and `message`. It asserts each expectation and exits non-zero on any mismatch, then `await kit.stop()` (adopt mode never stops the server).
- **Run and capture.** `feature=herdr-task-home; entry=@byokit/herdr; drive=(<lab wrapper> node "$scratch_dir/verify-herdr-task-home.mjs" <pi dir> <gemini.js>)`, where the wrapper provisions the lab session, passes its socket and a fresh task directory, and tears down on EXIT; then run SKILL.md Evidence's capture block. Exit code `0`.
- **record-home shows.** `HOME` is the task home and every `XDG_*_HOME` starts with it; the task home holds `byk-marker`, plus `.pi` unless the pane inherited a `PI_CODING_AGENT_DIR` outside it (the lab helper sets one, so there it holds only `byk-marker`).
- **launch-home shows.** `HOME` is the task home, the four `XDG_*` are unset and only the passed keys remain.
- **inside-view shows.** The pane prints `HOME=<task home>`, `task-home-marker` and `absent` for every personal folder.
- **existing-pane-refused shows.** `env_mismatch` with "This pane needs to be opened again to use that sign-in."
- **gemini-record-home shows.** As the call returns, `agent.get` can still report no kind (`unknown`) while Gemini relaunches; then the pane shows "How would you like to authenticate for this project?" and "No authentication method selected."; both Gemini processes (the wrapper's and Gemini's relaunch) end in `gemini.js` and carry `HOME`, `GEMINI_CLI_HOME`, `TMPDIR` and `GEMINI_FORCE_FILE_STORAGE` from the recipe, every `XDG_*_HOME` under the root and `HERDR_AGENT=gemini`; `agent.get` reports `gemini`, `idle` and ready; the root holds `.gemini/projects.json` beside `byk-marker` and no `oauth_creds.json`, `google_accounts.json` or `gemini-credentials.json`; 0 egress attempts.
- **gemini-folder-refused shows.** `sign_in_failed` with "This helper isn't ready yet. Try again in a moment."

## Gotchas

- Two `startAgent` calls of one kind without `name` collide on the server (`agent_name_taken`); give each a name.
- The lab session's socket path must stay under 108 bytes: a long session label or state directory makes `herdr server` exit silently and provisioning time out.
- Panes inherit the server's other variables under a record env; only `{ env, unset }` replaces them.
- Herdr 0.9.1 names a pane process by `/proc/<pid>/comm` and readies a Node-run Gemini only as `node` (Node 22): on Node 24 (`MainThread`) and Node 26 (`node-MainThread`) a plain start times out ("timed out waiting for agent startup"). The kit's own launch hint puts `HERDR_AGENT=gemini` on Gemini's process through the launch command (herdr-agent-hint.md); in the pane env the hint marks the shell itself as Gemini and `agent.start` refuses with `agent_pane_busy`, and a consumer-side wrapper is no longer needed.
- Keep Gemini's working folder outside `/home`: Gemini reads `.env` and `.gemini/` files from the working folder upward, so a folder under the person's home could reach their files.
- Cleanup: the lab wrapper's teardown stops the session; then SKILL.md Cleanup removes only "$scratch_dir" and confirms the evidence survives.
